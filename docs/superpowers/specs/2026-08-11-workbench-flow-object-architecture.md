# Flux 工作台流对象架构

日期：2026-08-11

## 产品判断

Flux 的一级产品形态从“画布工具”调整为“工作台”。无界画布继续负责流程定义、空间化编排和单次运行观察；工作台负责跨流程的运行总览、注意力分配和成果入口。

用户认知中的最小工作单元是流对象。流对象由流程定义与运行投影组成，但两者不能在持久化模型中混为一体。

## 边界

```text
流程定义（Workspace Repository） ─┐
                                ├─> Workbench Flow Projection ─> 工作台
运行快照（Scheduler / Cloud API）─┘

工作台 ──打开──> 无界画布 ──编排 / 运行命令──> Runtime
```

- `WorkflowSummary` 保持定义、发布和归属信息，不写入瞬时运行状态。
- `WorkbenchRuntimeSnapshot` 是只读运行投影，可由本地调度器或未来的云端聚合 API 提供。
- `WorkbenchFlowItem` 是页面读取模型，负责状态归一化、注意力优先级和筛选。
- 工作台可以观察运行状态并进入对应流程，但第一阶段不直接拥有画布保存、发布或执行命令。
- 缺少节点级执行数据时不得伪造百分比。运行中只显示不确定进度；后续由执行聚合 API 提供 `completedNodes / totalNodes` 后再显示确定进度。

## 状态归一化

| 工作台状态 | 来源 | 用户含义 |
| --- | --- | --- |
| 需要关注 | failed / invalid / paused | 失败、配置异常或等待人工确认 |
| 运行中 | running | 当前正在处理节点 |
| 等待触发 | waiting / idle + trigger | 已进入自动计划 |
| 最近完成 | success | 上次运行成功 |
| 可运行 | published，无运行快照 | 流程已发布但未设置自动计划 |
| 编辑中 | draft，无运行快照 | 流程定义尚未发布 |
| 非活动 | disabled / cancelled | 计划暂停或上次运行取消 |

## 第一阶段交付

1. 建立纯函数工作台投影层，并用单元测试锁定映射与优先级。
2. 工作台顶部提供全部、需要关注、运行中、等待触发、最近完成五个总览入口。
3. 每个流对象行展示定义状态、运行状态、下次触发或最近完成时间。
4. 保持打开画布、收藏、分享、导入导出和删除能力不变。

## 后续演进

- 云端增加工作空间级 execution summary 查询，返回正在运行、暂停、失败和节点进度。
- 人工确认形成独立待办投影，工作台可直接处理安全的确认动作。
- 成果对象与流对象关联，在工作台展示最近产出，而不是展示原始运行日志。
- 大量流对象时使用服务端分页或虚拟列表，投影层接口保持不变。
